# TASK-039 — Multi-Sensor Fusion Engine (2026-04-24)

## Summary
Implements a Naive-Bayes multi-sensor fusion engine that subscribes to all
`sensor:event:*` Redis channels, groups events into time-windowed clusters per
AOI, and publishes classified `FusionOutcome` objects to the `fusion:outcome`
channel.  Persistence and management endpoints are added to the backend.

---

## Analytics (`src/analytics/fusion/`)

### New package files

| File | Purpose |
|---|---|
| `__init__.py` | Empty package marker |
| `cluster.py` | `SensorEventCluster` dataclass + `cluster_events()` greedy grouping |
| `bayes.py` | `FusionWeights`, `FusionOutcome` (TypedDict), `compute_posterior()` |
| `weights_loader.py` | `load_weights()` — YAML or hardcoded defaults |
| `engine.py` | `FusionEngine` — async Redis subscriber + sync `process_window()` |
| `publisher.py` | `publish_fusion_outcome()` — non-fatal Redis pub to `fusion:outcome` |

### Outcome classes
`animal`, `human`, `group`, `vehicle`, `drone`, `gunshot`, `tunnel`, `unknown`

### Confidence threshold
Outcomes below **0.5** are suppressed; Redis publishes only happen above this floor.

### Render hints (TASK-038 compatible)
Each outcome class carries a `render_hint` dict with a `glyph` key and class-
specific extras (`radius_m`, `bearing_deg`, `arc_deg`, `decay_s`).

## Analytics API (`src/analytics/api/routes.py`)

Two new endpoints added to the existing router:

| Method | Path | Auth | Description |
|---|---|---|---|
| `POST` | `/fusion/process` | none (internal) | Synchronous fusion; returns outcomes ≥ 0.5 confidence |
| `GET` | `/fusion/health` | none (internal) | Returns weights loaded flag + per-AOI buffer sizes |

---

## Backend Prisma schema (`src/backend/prisma/schema.prisma`)

Two new models:

- **`FusionOutcome`** — persists ingested outcomes; indexed on `aoi_id` and `created_at`
- **`FusionWeight`** — stores admin-managed per-class priors and likelihoods

---

## Backend routes (`src/backend/src/routes/fusion.ts`)

Registered in `src/backend/src/index.ts` as `fusionRoutes`.

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/aoi/:id/outcomes` | VIEWER+ | Paginated outcome history for an AOI |
| `GET` | `/fusion/weights` | VIEWER+ | List all weight entries |
| `PUT` | `/fusion/weights` | ADMIN | Upsert a weight entry |
| `POST` | `/fusion/outcomes` | ADMIN \| ENGINEER | Ingest outcome; publishes `alert:new` if confidence ≥ 0.75 |

## Tests (`src/analytics/tests/test_fusion.py`)

Seven test functions covering:
1. `test_cluster_groups_close_events` — 3 events within 2 s → 1 cluster
2. `test_cluster_splits_distant_events` — 10 s gap → 2 clusters
3. `test_cluster_empty_input_returns_empty` — edge case
4. `test_posterior_human_from_seismic_footstep` — footstep + voice → human/group
5. `test_posterior_vehicle` — seismic_vehicle + acoustic_vehicle → vehicle
6. `test_render_hint_human` — glyph = footstep_radius
7. `test_render_hint_tunnel` — glyph = tunnel, arc_deg = 360
8. `test_process_window_below_threshold_returns_none` — flat weights → None
9. `test_process_window_returns_outcome_above_threshold` — strong vehicle signal → outcome

## Security notes
- Raw event payloads (which may include sensor coordinates) are never logged
- `publish_fusion_outcome` logs only `type(exc).__name__`, never Redis URLs
- Backend ingest endpoint requires ADMIN or ENGINEER role
- Weight management requires ADMIN role
