## Summary

Implemented the full AOI (Area of Interest) REST API at `src/backend/src/routes/aoi.ts` and registered it in `src/backend/src/index.ts`.

## Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/aoi` | VIEWER+ | List all active (non-deleted) AOIs. Accepts optional `?bopZoneId` filter. Returns parsed GeoJSON geometry (never raw `geometryJson`). |
| POST | `/aoi` | ADMIN \| OPERATOR | Create a new AOI. Validates Polygon geometry (min 6 coords, max 1000 vertices). Emits `aoi:created` Redis pub/sub event (non-fatal if Redis unavailable). |
| PATCH | `/aoi/:id` | ADMIN \| OPERATOR | Partial update of name, bopZoneId, and/or geometry. Returns 404 for soft-deleted records. |
| DELETE | `/aoi/:id` | ADMIN | Soft-deletes by setting `deletedAt`. Returns 204. |
| GET | `/aoi/:id/export` | VIEWER+ | Export AOI as GeoJSON FeatureCollection with `Content-Type: application/geo+json`. |
| POST | `/aoi/import` | ADMIN \| OPERATOR | Bulk import from GeoJSON FeatureCollection. Invalid features are skipped; returns `{ created, skipped }`. |

## Security

- Geometry is always sanitised via JSON round-trip before storage to prevent prototype pollution.
- Coordinate values (lat/lon) are never logged at `info` level.
- Camera/user credentials are not touched by this route.
- All endpoints require JWT auth (`verifyJwt` + `requireRole`).
- Input validated with Zod on every handler.
