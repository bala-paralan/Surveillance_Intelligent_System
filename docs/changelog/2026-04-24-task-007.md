## What was built

Added camera intrusion-zone management to the Fastify backend.

### Prisma schema changes (`src/backend/prisma/schema.prisma`)

- Added `cameraZones CameraZone[]` relation to the `Camera` model.
- Added `CameraZone` model:
  - Fields: `id`, `cameraId`, `zoneId`, `label?`, `polygon` (JSON), `createdAt`, `updatedAt`
  - Unique constraint on `(cameraId, zoneId)`
  - Cascade delete from `Camera`
  - Table: `camera_zones`

### New route file (`src/backend/src/routes/zones.ts`)

| Endpoint | Auth | Description |
|----------|------|-------------|
| `GET /cameras/:cameraId/zones` | VIEWER+ | Returns all zones for a camera |
| `POST /cameras/:cameraId/zones` | ADMIN, OPERATOR | Upserts zones for a camera (atomic transaction); forwards to analytics microservice (fire-and-forget) |

### Validation (Zod)

- `zoneId`: string 1–64 chars
- `polygon`: array of `[x, y]` pairs (both in `[0, 1]`), min 3 vertices, max 50 vertices
- `label`: optional string max 120 chars
- Max 100 zones per POST

### Analytics forwarding

After a successful DB write, the zones are forwarded to the analytics microservice (`POST {ANALYTICS_URL}/zones`) with a 3-second timeout. Failures are logged at WARN level and never surface to the API caller.
