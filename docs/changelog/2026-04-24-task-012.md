### Prisma models

- **RecordingSchedule** — cron-based schedule (`cronExpr`, `durationS`), linked to `Camera`
- **Recording** — full lifecycle record: `SCHEDULED → RECORDING → STORED`, with `storagePath` (object storage key only), `storageTier`, `fileSizeBytes`

### BullMQ job types

| Job | Trigger | What it does |
|---|---|---|
| `start-recording` | `scheduleRecording()` or cron | Creates Recording row, calls `startStream()`, schedules `stop-recording` with delay |
| `stop-recording` | Delayed by `durationS` | Calls `stopStream()`, assigns placeholder S3 path, marks `STORED` |
| `tier-migrate` | Manual / lifecycle policy | Updates `storageTier` on Recording |

### REST endpoints

| Method | Path | Auth |

### Security compliance
- `storagePath` (S3 key) is NEVER included in API responses — `toPublicRecording()` explicitly omits it
- Raw video is NEVER stored on the application server — `buildStoragePath()` generates a placeholder `s3://` URI
- Export endpoint returns pre-signed URL placeholder; production uses AWS SDK / MinIO `presignedGetObject`
- BullMQ retries failed jobs up to 3× with exponential backoff
