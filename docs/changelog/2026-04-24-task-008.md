## Backend

### Prisma schema changes (`src/backend/prisma/schema.prisma`)

Added two new enums and one model:

- `enum AlertType` — INTRUSION, MOTION, PERSON, VEHICLE, SEISMIC, ACOUSTIC, SYSTEM
- `enum AlertSeverity` — CRITICAL, HIGH, MEDIUM, LOW
- `model Alert` — id, type, severity, cameraId?, bopZoneId?, aoiId?, message, metadata (JSON)?, acknowledged, acknowledgedBy?, acknowledgedAt?, resolvedAt?, createdAt
  - Indexes on `cameraId`, `bopZoneId`, `acknowledged`, `createdAt`
  - Table: `alerts`

### New route file (`src/backend/src/routes/alerts.ts`)

| Endpoint | Auth | Description |
|----------|------|-------------|
| `GET /alerts` | VIEWER+ | Paginated list; filters: acknowledged, severity, bopZoneId, aoiId, limit (max 200), offset |
| `POST /alerts` | ADMIN, OPERATOR, ENGINEER | Creates alert; publishes to Redis `alerts:new` (non-fatal) |
| `PATCH /alerts/:id/acknowledge` | OPERATOR, ADMIN | Sets acknowledged=true, records acknowledgedBy and acknowledgedAt |
| `PATCH /alerts/:id/resolve` | OPERATOR, ADMIN | Sets resolvedAt timestamp |
| `GET /alerts/stats` | VIEWER+ | Returns count by severity for last 24 h |

`metadata` field is excluded from list responses for performance; included only on the `POST` response body.

Redis publish to `alerts:new` is non-fatal (warn-logged on failure).

## Frontend

Typed API client with functions: `listAlerts`, `createAlert`, `acknowledgeAlert`, `resolveAlert`, `getAlertStats`.  All calls route through the existing `apiFetch` client (auto token refresh).

### `src/frontend/src/components/alerts/AlertFeed.tsx`

- Fetches `GET /alerts?acknowledged=false&limit=20` via react-query
- `staleTime: 10_000`, `refetchInterval: 10_000` (10-second auto-refresh)
- CRITICAL alerts sorted to top; all alerts sorted by severity then recency
- Severity colour badges: CRITICAL=red, HIGH=orange, MEDIUM=yellow, LOW=blue
- Acknowledge button visible for ADMIN and OPERATOR roles only
- "No active alerts" empty state with checkmark icon
- Loading and error states handled
